ITEM C: AI EMERGENCY STOP AND CANCELLATION
- Version 5 Defect: Referenced non-existent hypothetical function `llama_cancel_eval()`.
- Version 6 Correction:
  1. Replaced with official upstream API: `llama_set_abort_callback(ctx, abort_callback, user_data)`.
  2. Registered callback checks an atomic thread-safe flag (`std::atomic<bool>`) between decode cycles.
  3. When signaled, active CPU decoding halts immediately and returns control to the daemon loop.
  4. Local HTTP streams are closed via `SO_LINGER(0)` socket abort; helper processes killed via SIGTERM/SIGKILL.
  5. Realism Disclosure: Local TCP reset aborts client data streams, but CANNOT retract data already
     transmitted or guarantee remote cloud providers will not bill for in-flight requests.
  6. Memory buffers are zeroized using `explicit_bzero()`.
- Target Documents: `KAATYA_STAGE2_2_AI_SECURITY_PRIVACY_AND_PROVIDER_SPECIFICATION_v6.txt`.
