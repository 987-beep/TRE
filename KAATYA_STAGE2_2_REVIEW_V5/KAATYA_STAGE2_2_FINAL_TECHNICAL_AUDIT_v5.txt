C. NEMOTRON KV CACHE MEMORY CALCULATIONS: FORMULAS & ARCHITECTURAL REALITIES
--------------------------------------------------------------------------------
Standard Full-Attention KV Cache Formula (per token):
  Bytes_per_token = 2 * n_layers * n_kv_heads * head_dim * bytes_per_element

1. Naive Full-Attention Calculation (Assuming all 42 layers use head_dim=512, FP16):
   - Bytes_per_token = 2 * 42 * 2 * 512 * 2 = 172,032 bytes = 168.0 KiB/token
   - At C = 4,096 tokens:  704,643,072 bytes   = 672.00 MiB (0.6562 GiB)
   - At C = 8,192 tokens:  1,409,286,144 bytes = 1,344.00 MiB (1.3125 GiB)
   - At C = 16,384 tokens: 2,818,572,288 bytes = 2,688.00 MiB (2.6250 GiB)
   - At C = 32,768 tokens: 5,637,144,576 bytes = 5,376.00 MiB (5.2500 GiB)
   - At C = 65,536 tokens: 11,274,289,152 bytes = 10,752.00 MiB (10.5000 GiB)
   *Note: This mathematically confirms the review finding: under simple full attention,
    8K context requires ~1.3125 GiB and 65K context requires ~10.5 GiB.*

2. Actual Gemma4 Hybrid SWA Calculation (Assuming llama.cpp ring-buffer SWA support):
   - SWA Layers (35 layers): Tokens capped at W = 512 tokens.
     SWA_bytes_per_token = 2 * 35 * 2 * 256 * 2 = 71,680 bytes = 70.0 KiB/token.
     Max SWA Cache = 512 * 71,680 = 36,700,160 bytes = 35.00 MiB (Fixed constant).
   - Global Layers (7 layers): Stores full context C tokens with head_dim=512.
     Global_bytes_per_token = 2 * 7 * 2 * 512 * 2 = 28,672 bytes = 28.0 KiB/token.
   - Combined Formula: Total_KV = SWA_Cache + (C * Global_bytes_per_token)
   - At C = 4,096 tokens:  35.0 MiB + 112.0 MiB = 147.00 MiB (0.1436 GiB)
   - At C = 8,192 tokens:  35.0 MiB + 224.0 MiB = 259.00 MiB (0.2529 GiB)
   - At C = 16,384 tokens: 35.0 MiB + 448.0 MiB = 483.00 MiB (0.4717 GiB)
   - At C = 32,768 tokens: 35.0 MiB + 896.0 MiB = 931.00 MiB (0.9092 GiB)
   - At C = 65,536 tokens: 35.0 MiB + 1792.0 MiB = 1,827.00 MiB (1.7842 GiB)

3. Crucial llama.cpp Runtime Condition (UNVERIFIED STATUS):
   - Current llama.cpp upstream builds may not implement per-layer heterogeneous KV

   - If llama.cpp allocates a uniform KV buffer using maximum layer dimensions

Memory Accounting Distinctions:
- Physical RSS: Actually resident dirty/anonymous memory pages occupying physical RAM.
- Mapped Files (mmap): Clean file-backed pages (e.g. model weights) discardable under pressure.
- GPU Shared Memory: System RAM dynamically assigned to Intel HD 530 Mesa driver.
- Virtual Memory (VIRT): Address space reservations, not physical RAM allocation.
- Compressed zram: Compressed pool residing within physical RAM providing expanded virtual space.
