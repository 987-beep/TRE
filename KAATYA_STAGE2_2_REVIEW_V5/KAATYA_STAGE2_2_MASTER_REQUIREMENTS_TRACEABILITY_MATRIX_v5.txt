1. EIGHT-STAGE EVIDENCE & VERIFICATION TAXONOMY
--------------------------------------------------------------------------------
To eliminate ambiguous or premature "Verified" classifications, KAATYA OS 3.0
enforces an 8-stage evidence hierarchy for every architectural requirement:

[Stage 1] Requirement Documented: Written specification exists in master documentation.
[Stage 2] Architecture Selected: Specific technical library, daemon, or standard defined.
[Stage 3] Asset Metadata Inspected: Header or configuration metadata parsed and verified.
[Stage 4] Asset Hash Verified: Cryptographic SHA-256 hash calculated and matched against disk.
[Stage 5] Code Implemented: Handwritten source code, build scripts, or recipes created.
[Stage 6] Functional Test Passed: Unit/integration test passed in local build harness.
[Stage 7] Virtual-Machine Test Passed: Validated inside headless QEMU virtual machine.
[Stage 8] Physical Hardware Test Passed: Validated on physical HP Slimline PC 270-p0xx.

CRITICAL EVIDENCE AUDIT RULE:
Inspecting a model file, voice asset, or ISO on disk satisfies ONLY Stages 1 through 4.
It DOES NOT satisfy Stages 5 through 8. No requirement is marked "Complete" until
all applicable stages pass.
