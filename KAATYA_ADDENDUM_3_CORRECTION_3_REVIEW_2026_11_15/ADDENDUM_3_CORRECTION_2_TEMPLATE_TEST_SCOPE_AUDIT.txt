3. API PATHWAYS: COMMON WRAPPER VS DIRECT JINJA ENGINE
================================================================================
`tests/test-chat-template.cpp` evaluates two distinct execution paths:

1. High-Level Common API (`common_chat_template_render`):
   - Located in `common/chat.cpp`.
   - Reads model metadata, extracts parameters (`add_generation_prompt`, `bos_token`, `eos_token`, 
     `tools`, `chat_template_kwargs`), constructs the template context, and formats the output.
   - Tested by default across all standard test cases.

2. Direct Jinja Engine (`minja::Parser` / `minja::Template`):
   - Directly executes the C++ Jinja templating interpreter without CLI parameter wrapping.
   - Evaluated when `--no-common` is invoked or in standalone unit tests for Jinja expressions 
     (e.g., loops, conditionals, filters, macros).

6. OPERATIONAL BOUNDARIES & TEST LIMITATIONS
================================================================================
`tests/test-chat-template.cpp` is strictly a string rendering test harness.
It DOES NOT test:
1. Tokenizer Correctness: Does not test whether rendered strings map to correct vocab IDs.
2. Tensor Execution / GPU Inference: Does not execute any GEMM, attention, or neural network layers.
3. Model KV Cache: Does not test KV cache allocation, layer reuse, or SWA windowing.
4. Tool Call Execution: Does not execute external tools or validate client-side round-trips.

Passing this test only proves that the Jinja parser renders text according to hardcoded strings for 
the 12 models listed above.
